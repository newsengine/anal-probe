10 categories, one request

Everything wrong with a deploy

Each finding is signature-validated to keep false positives near zero, and ships with a plain-English fix.

🔑

Leaked secrets

API keys, tokens & private keys in your HTML and JS bundles — Stripe, AWS, Supabase service_role, GitHub. Source maps too.

📂

Exposed files

.env / .git / configs, backups, debug & admin endpoints, directory listings, GraphQL introspection, stack traces.

🔐

Security & TLS

Headers, CSP linting, cookies, CORS, open-redirect, SRI, and TLS protocol/cipher grading over a raw socket.

🌐

DNS & email

SPF, DMARC (with policy strength), CAA, and a dangling-CNAME subdomain-takeover heuristic. Correct on .com.au.

🧩

Framework-aware

Fingerprints the stack, then probes its known misconfigs — Next.js, WordPress, Laravel, Django, Rails, Spring, ASP.NET.

🖥️

Host intel

Resolved IPs, reverse DNS, and CDN/hosting provider — so you know whether an IP is your origin or an edge.

🤖

Agent-readiness

llms.txt, AI-crawler policy, JS-only content, and structured data — is your site consumable by AI agents?

🔗

Reliability & SEO

Broken links & images, mixed content, title/description/canonical, robots & sitemap, accessibility, performance.

One tool, escalating depth

Modes

The default scan is passive and safe. The aggressive modes are opt-in, authorization-gated, and identify-only — never exploit.

default
anal-probe <url>

Scan

The full 10-category black-box scan. Multi-page with --crawl, behind login with --cookie.

deps
anal-probe audit

Dependency CVEs

Wraps npm audit and gates CI on severity, against the advisory database.

nvd
anal-probe cve <svc> <ver>

CVE lookup

Correlate a detected service + version against NVD. Also wired into recon with --cve.

opt-in
anal-probe recon <host>

Active recon

Authorization-gated, CDN-guarded port scan + banner/service/version ID. Identify-only — no exploitation, no DoS.

batteries
anal-probe browse <url>

Functional check

Headless browser: JS errors, broken images, failed requests, and whether forms actually accept input.

batteries
anal-probe separation cfg

Account separation

Drives two logged-in profiles to prove account B can't read account A's data. Read-only, no passwords.

The line we don't cross

Safe to run against production

  • No attack payloads. GET-only scanning — no SQLi/XSS fuzzing that could break a live app.
  • Identify, never exploit. Recon reports open services; it never weaponizes them.
  • Authorization-gated. Port scanning refuses to run unconfirmed, and won't scan a CDN edge.
  • Zero-install, zero-dependency. One npx command; the committed build runs in CI with no bundler.
  • No passwords handled. Authenticated modes reuse your own logged-in browser profiles.
  • Low false positives. Every exposure is body-validated; SPA fallbacks don't trip it.
